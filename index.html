Summit proximity index

Sourced from Akhil Patel, The Secret Wealth Advantage (chapters 10, 12 and 14). Tags show how each sign typically feels at the time — the book's core warning is that most pre-Summit signals read as good news. The proximity index weights Summit-stage signs most heavily, then Mania, then Land Boom.

Each card links to its live data desk: FRED and Federal Reserve series for the chartable signs, official databases where they exist (CTBUH, BIS, NAR, Census), and curated news or Google Trends searches for the signs that can only be observed, not measured. Sources open in a new tab; if a link ever goes stale, the series name is enough to find it again.

To use the AI: upload this file to claude.ai and ask Claude to "open this file as an artifact exactly as-is". "Run AI update" then researches all 28 signs with live web search and sets every status, adding a dated evidence summary to each card; further passes gather market context for the playbook and the Bitcoin cycle desk. You can override any verdict with the status chips — overridden cards are labelled. Opened as a plain file in any browser, everything works too — the AI button just needs an Anthropic API key (⚿ next to it; stored only in that browser, never in the file), and progress saves in that browser instead.

A framework for observation, not financial advice. Cycle theories fit history more neatly in hindsight than in real time.

Put this page on the web (free, ~10 min, no coding)
  1. Create a GitHub account — go to github.com/signup, pick a username, verify your email. Free tier is all you need.
  2. Make a repository — click the + (top right) → New repository. Name it anything (e.g. summit-watch), set it to Public, tick Add a README, click Create repository.
  3. Upload this file — in the repo, click Add file → Upload files. Before uploading, rename your copy of this file to index.html (that exact name makes it the homepage). Drag it in, click Commit changes. Tip: use a copy made with Share seeded copy below if you want your current readings baked in — but remember a public page shows your notes to anyone with the link.
  4. Turn on GitHub Pages — repo Settings → Pages (left sidebar). Under "Build and deployment," set Source to Deploy from a branch, branch main, folder / (root), click Save.
  5. Get your link — wait 1–2 minutes, refresh the Pages settings page, and your site appears at https://YOUR-USERNAME.github.io/summit-watch/. Send that URL to anyone.
  6. Update later — to publish new readings, click Share seeded copy, rename the download to index.html, and upload it to the repo again (Upload files → drag → Commit). The site updates itself in a minute or two.

On the hosted page everything works for every visitor — chips, notes, gauge, saved progress (per browser). The AI update button needs either an Anthropic API key (⚿ in the header, each visitor's own) or the page opened inside claude.ai instead. Never put an API key in the repo itself.
